## 1. 部署边界

当前只提供**本地 Python 进程 + CLI** 的运行方式：

| 形态 | 状态 |
|---|---|
| 本地离线评测（A0/A3） | 已支持，零第三方依赖 |
| 本地在线评测（A3L/A3R/A4/A4R） | 已支持，需要 DeepSeek 密钥与 `[llm]` 依赖 |
| Docker 镜像 | 未提供（路线图 S2） |
| MCP Server | 未提供（路线图 S2） |
| OpenTelemetry | 未接入（路线图 S2） |
| HTTP 服务 / 常驻进程 | 未提供 |
| 并发批量吞吐 | 未提供，当前逐条串行 |

## 2. 环境要求

- Python ≥ 3.10（CI 覆盖 3.10 / 3.11 / 3.12）
- Git
- 可选：`uv`（CI 使用 `uv sync --frozen --all-extras`）
- 在线评测：可访问 `https://api.deepseek.com` 的网络与有效 API Key

## 3. 安装

### 3.1 离线安装（只跑 A0/A3 与测试）

```bash
python -m pip install -e ".[dev]"
```

### 3.2 在线安装（需要真实模型调用）

```bash
python -m pip install -e ".[dev,llm]"
```

### 3.3 uv（与 CI 一致）

```bash
uv sync --frozen --all-extras
uv run pytest
```

> `httpx` 与 `tenacity` 只在 `[llm]` 中；只装 `[dev]` 时在线臂会因缺少依赖失败。

## 4. 数据生成

所有命令从**仓库根目录**执行。

```bash
# 1) 基础公开轨：12 条干净对话（seed 固定，产物可复现）
python -m agent.benchmark.fixtures --n 12 --seed 20261112

# 2) dev / test 分层切分：30 + 50，互不重叠
python -m agent.benchmark.fixtures \
  --dev-out agent/fixtures/public/dev_v1.json \
  --test-out agent/fixtures/public/test_v1.json

# 3) 六类缺陷注入：6 × 20 = 120 条
python -m agent.benchmark.defects \
  --per-type 20 --seed 20261113 \
  --out agent/fixtures/public/defects_v1.jsonl

# 4) 分布校准档：默认 120 条，产物与 v1 分开
python -m agent.benchmark.fixtures --profile realistic

# 5) 分布校准档 dev / test 分层切分：40 + 80
python -m agent.benchmark.fixtures --profile realistic \
  --dev-out agent/fixtures/public/realistic_dev_v1.json \
  --test-out agent/fixtures/public/realistic_test_v1.json
```

说明：

- `--profile` 默认 `v1`；`realistic` 是用私有轨聚合分布校准的公开档，只使用轮次直方图、唯一率、重复率、长度分位与实体密度，不含任何原文或业务标签。
- 切分模式由 `--dev-out` / `--test-out` 任一非空触发；`v1` 默认 `--dev-n 30 --test-n 50 --split-seed 20261118`，`realistic` 默认 `--dev-n 40 --test-n 80 --split-seed 20261124`。
- `test_v1.json` 只用于最终结论，不用于调 prompt。
- 重新生成后若 `base_v1.json` 字节变化，A0 基线会校验失败；这是预期保护，不要用 `--force` 绕过。
- `realistic` 产物**不**与 `baseline_lock.json` 绑定，只用于分布对照与鲁棒性实验，不能替代 §5 的冻结基线复现。

## 5. 离线验证

```bash
# 全量测试（含开源边界自证）
python -m pytest

# 复现冻结基线（CI 同款）
python -m agent.benchmark.run \
  --input agent/fixtures/public/base_v1.json \
  --arms A0 \
  --verify-arm A0
```

预期输出：

```text
[OK] 臂 A0 产物指纹复现一致
```

CI（`.github/workflows/ci.yml`）还会检查：

1. `baseline_lock.json` 的 `code.dirty` 必须为 `false`；
2. Python 3.10–3.12 矩阵全部跑通；
3. A0 复现命令通过。

## 6. 在线评测

### 6.1 配置密钥

```bash
cp .env.example .env
```

编辑 `.env`：

```dotenv
DEEPSEEK_API_KEY=sk-...
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
JUDGE_MODEL=
```

- `.env` 不入库；密钥只走环境变量。
- `JUDGE_MODEL` 留空时沿用生成侧模型；建议配置跨模型家族的判官以降低自我偏好。
- 判官温度固定为 0。

### 6.2 运行臂

```bash
# A3L：LLM 决策 + 确定性工具
python -m agent.benchmark.agent_eval --arm A3L --live \
  --out agent/benchmark/output/ablation_A3L.json

# A3R：规则多轮 + rewrite_segment
python -m agent.benchmark.agent_eval --arm A3R --live \
  --out agent/benchmark/output/ablation_A3R.json

# A4：LLM 决策 + 语义判官
python -m agent.benchmark.agent_eval --arm A4 --live \
  --out agent/benchmark/output/ablation_A4.json

# A4R：A4 + rewrite_segment（--review 导出 repaired 样本供人工抽检）
python -m agent.benchmark.agent_eval --arm A4R --live \
  --out agent/benchmark/output/ablation_A4R.json \
  --review logs/agent/review_A4R.md

# A3：离线规则臂（不需要 --live）
python -m agent.benchmark.agent_eval --arm A3 \
  --out agent/benchmark/output/ablation_A3.json
```

调试时可加 `--limit 2`（每类最多 2 条），但**调试结果不能写入结论**。

### 6.3 私有轨 / 无标签数据（观测模式）

`--input` 可指向任意对话 JSON（如 `agent/fixtures/private/` 下的真实数据）。只给 `--input`、不给 `--defects` 时进入**观测模式**：

```bash
python -m agent.benchmark.agent_eval --arm A3 \
  --input agent/fixtures/private/<file>.json \
  --limit-base 20 \
  --out logs/agent/smoke_private_A3.json
```

- 观测模式数据没有缺陷标签，只产出干净样本干预率、失败/中止、成本等**无标签指标**；`macro_recall_*` 恒为 0，不能当作检出率。
- 要用真实数据算检出率，先用 `python -m agent.benchmark.defects --input <file> --out <defects>.jsonl` 注入缺陷，再用 `--defects` 指过去。
- `--limit-base` 只控制观测模式的样本数；有 `--defects` 时使用 `--limit`。
- 私有轨只允许发布聚合指标（ADR D6）；结果写 `logs/`，不入库。

### 6.4 成本与账本

- ledger 固定写到 `logs/agent/ledger_<arm>.jsonl`，append-only，失败调用与缓存命中都记录。
- 结果 JSON 的 `tokens`、`calls`、`cost_cny` 取自同一 ledger 的区间增量。
- 成本按版本化价格表折算；报告中必须注明价格表版本。
- `logs/` 当前未被 `.gitignore` 忽略，提交前不要 `git add logs/`。

## 7. 报告生成

```bash
python -m agent.benchmark.report \
  --results agent/benchmark/output \
  --trace logs/agent/trace.jsonl \
  --out portfolio/agent-augmentation
```

- `--trace` 与 `--case` 可选；没有时对应图仍会生成空数据版本。
- `--results` 可以是目录，自动收集 `ablation_*.json`。

产物：

```text
portfolio/agent-augmentation/
├── benchmark_report.json
├── benchmark_report.md
├── benchmark_report.html
└── figures/
    ├── 01_ablation.svg
    ├── 02_heatmap.svg
    ├── 03_trace_timeline.svg
    └── 04_before_after.svg      # 仅 --case 时
```

## 8. 产物与版本管理

| 路径 | 是否入库 | 说明 |
|---|---|---|
| `agent/benchmark/baseline/baseline_lock.json` | 入库 | 冻结基线唯一真源，只读 |
| `agent/benchmark/baseline/lock_changelog.md` | 入库 | 每次 `--force` 的变更理由 |
| `agent/benchmark/output/` | 不入库 | 运行产物、报告、manifest |
| `agent/fixtures/public/` | 入库 | 公开轨数据 |
| `agent/fixtures/private/` | 不入库 | 仅主工程使用，本仓库不存在 |
| `logs/` | 不入库（约定） | ledger 与 trace；当前需人工避免误提交 |
| `.env` | 不入库 | 本地密钥 |

## 9. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `[ERROR] 未找到 DEEPSEEK_API_KEY`（退出码 2） | 未配置密钥 | 检查 `.env` 或环境变量；不要在命令里明文传 key |
| `ModuleNotFoundError: httpx` / `tenacity` | 只装了 `[dev]` | 安装 `.[dev,llm]` 或 `uv sync --all-extras` |
| `LockViolation` / 基线指纹不一致 | 输入、配置、评估器或适配指纹变化 | 确认变更是否符合预期；确需更新用 `--force --reason` 并提交 changelog |
| `[FAIL] 臂 A0 产物指纹不一致` | 数据或代码变化导致产物变化 | 先定位差异；入库锁必须由 clean 工作区生成 |
| 入库锁被 CI 拒绝：`dirty=true` | 在未提交状态下生成 lock | 提交代码后，从 clean 工作区重新生成 |
| `stopped` 数量异常偏高 | 宿主机休眠、网络挂起导致墙钟预算触发 | 唤醒后复跑；不要把 `stopped` 当作“未检出” |
| 找不到 fixture | 不在仓库根目录执行 | 所有默认路径都相对于当前工作目录 |
| Windows 路径报错 | 反斜杠或中文路径未加引号 | PowerShell 中用双引号包裹路径；优先使用正斜杠 |
| `test_oss_boundary` 失败：文件未登记 | 新增/移动文档后未更新清单 | 在 `agent/oss_manifest.txt` 的 PUBLIC 段登记 |

## 10. 复现检查清单

- [ ] Python 版本 ≥ 3.10，依赖按 `pyproject.toml` 安装；
- [ ] 数据由固定 seed 重新生成，`base_v1.json` 未手工修改；
- [ ] `python -m pytest` 全绿；
- [ ] `--verify-arm A0` 输出 `[OK]`；
- [ ] 在线结果带 `fingerprint`，同目录有 `manifest_<arm>.json`；
- [ ] 报告中注明价格表版本、`n`、`stopped` 与 `failed`；
- [ ] 未把 `output/`、`logs/`、`.env` 提交进仓库。
