# Ollama 本地部署与远程调用

> 记录：2026-11-19
> 适用：服务器（4090 GPU + 4 核 CPU）+ 本地开发机远程联调
> 关联：配置模板 `.env.example`（DEEPSEEK_* / JUDGE_* / JUDGE_BASE_URL）

---

## 1. 模型与硬件匹配

4090 = 24GB 显存。Ollama Q4_K_M 量化下的典型占用：

| 模型 | Q4 显存 | 4090 能跑 | 推荐用途 |
|------|---------|---------|---------|
| 7B ~ 14B | 4 ~ 8 GB | ✅ 同时跑俩 | judge（轻量、高吞吐） |
| 30B ~ 32B | 18 ~ 19 GB | ✅ 单模型刚好 | rewrite（重度、需要 tool calling） |
| 70B | ~43 GB | ❌ 溢出到 RAM | 不推荐 |

4090 跑 benchmark 的**推荐组合**（跨模型家族隔离，速度/显存甜点）：

| 角色 | 模型 | 理由 |
|------|------|------|
| **rewrite / decide** | `qwen3-coder-30b:latest` (17GB) | 有 tool calling，30B 中文改写够用 |
| **judge** | `qwen2.5:14b` (~8GB) | 无需 tool calling，14B JSON 输出稳定，吞吐高 |

**关键**：Ollama `keep_alive=0` 时模型用完自动卸载——两个模型不需要同时塞显存。

## 2. 模型名/Tag 铁律

### ❌ 坑过我的
```bash
# qwen3-coder:30b  ≠  qwen3-coder-30b:latest
# Ollama 认为是两个不同的模型 → 本地没有 → 重新 pull
ollama run qwen3-coder:30b   # ❌ 重拉 17GB
ollama run qwen3-coder-30b:latest  # ✅ 秒出
```

### ✅ 正确姿势
```bash
# 1. 先看本地到底有什么
ollama list

# 2. 搜官方到底有哪些 tag
ollama search qwen3-coder

# 3. 显式指定完整 tag（name:tag）
ollama run qwen3-coder-30b:latest
```

## 3. 服务启动与环境变量

### systemd 启动（服务器上永久生效）

```bash
# 查看当前服务配置
systemctl show ollama | grep -i env

# 当前服务器配置（已确认）：
# OLLAMA_NUM_THREADS=4
# OLLAMA_MODELS=/home/zimeng/ollama_models
# 注意：没有 OLLAMA_HOST → 默认只绑 127.0.0.1，外部连不上

# 永久加 OLLAMA_HOST=0.0.0.0:11434
sudo systemctl edit ollama
# 写入：
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_NUM_THREADS=4"
Environment="OLLAMA_MODELS=/home/zimeng/ollama_models"
Environment="OLLAMA_NUM_PARALLEL=1"
Environment="OLLAMA_KEEP_ALIVE=0"

# 生效
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

### 环境变量速查

| 变量 | 默认 | 说明 |
|------|------|------|
| `OLLAMA_HOST` | `127.0.0.1:11434` | 绑定地址；0.0.0.0 开放远程 |
| `OLLAMA_MODELS` | `~/.ollama/models` | 模型存储目录 |
| `OLLAMA_NUM_THREADS` | CPU 核数 | CPU 解码线程数；服务器 4 核设 4 |
| `OLLAMA_NUM_PARALLEL` | 1 | 并发推理数；4090 单卡固定 1 避免显存挤爆 |
| `OLLAMA_KEEP_ALIVE` | 5m | 模型在显存停留时间；0=用完立刻卸载 |

## 4. 模型管理

```bash
# 拉模型
ollama pull qwen2.5:14b
ollama pull qwen3-coder-30b:latest

# 列出所有已下载
ollama list

# 查看正在运行（跑 benchmark 时用）
ollama ps

# 删除模型
ollama rm qwen2.5:14b

# 模型总占用
du -sh /home/zimeng/ollama_models/

# 清理半拉子 pull 残留（Ctrl+C 中断后用）
rm -rf /home/zimeng/ollama_models/blobs/*partial*

# 验证能跑
ollama run qwen3-coder-30b:latest "你好"
```

## 5. 远程调用（家里 → 服务器）

### 方式 A：SSH 隧道（推荐，不需要改防火墙）

家里电脑执行：
```bash
# -L 本地端口:目标主机:目标端口
# 把家里 11434 → 服务器 127.0.0.1:11434
ssh -L 11434:localhost:11434 zimeng@服务器IP -N
# 保持这个终端开着
```

家里的 `.env`：
```bash
DEEPSEEK_MODEL=qwen3-coder-30b:latest
DEEPSEEK_BASE_URL=http://localhost:11434/v1
JUDGE_MODEL=qwen2.5:14b
JUDGE_BASE_URL=http://localhost:11434/v1
```

### 方式 B：服务器暴露公网端口

服务器端：
```bash
sudo systemctl edit ollama
# Environment="OLLAMA_HOST=0.0.0.0:11434"
sudo systemctl restart ollama
sudo ufw allow 11434/tcp
# 云厂商安全组也要放行（阿里云/腾讯云控制台）
```

家里的 `.env`：
```bash
DEEPSEEK_BASE_URL=http://服务器公网IP:11434/v1
JUDGE_BASE_URL=http://服务器公网IP:11434/v1
```

## 6. 本项目 .env 模板

```bash
# ---- 服务器全 Ollama ----
DEEPSEEK_API_KEY=ollama
DEEPSEEK_MODEL=qwen3-coder-30b:latest
DEEPSEEK_BASE_URL=http://localhost:11434/v1

JUDGE_MODEL=qwen2.5:14b
JUDGE_BASE_URL=http://localhost:11434/v1

# ---- 混合：生成走商用 API，判官走 Ollama ----
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com

JUDGE_MODEL=qwen2.5:14b
JUDGE_BASE_URL=http://localhost:11434/v1

# ---- 本地开发：共用 deepseek-chat（测试 L3 compare 时用）----
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_MODEL=deepseek-chat
# JUDGE_* 留空 → 自动沿用 DEEPSEEK_*
```

判官强制 `temperature=0.0`（config.py 里硬设），不通过 env 覆盖。

## 7. 排障清单

| 现象 | 先查 |
|------|------|
| `ollama list` 空 | `OLLAMA_MODELS` 环境变量 vs systemd override 里的值是否一致 |
| `ollama run xxx` 重新 pull | 模型 tag 拼写 vs `ollama list` 里的完整 name:tag |
| 远程 curl 11434 连不上 | ① 服务器 ollama 绑定了 0.0.0.0 吗 ② ufw / 云安全组放行了吗 |
| 显存溢出 OOM | `OLLAMA_KEEP_ALIVE=0` + `OLLAMA_NUM_PARALLEL=1` |
| 速度慢 | `ollama ps` 看是否有俩模型同时常驻显存 |
