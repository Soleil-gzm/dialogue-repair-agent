## 1. A1 原本是什么

A1 是"现有能力基线"：调用主工程上游 `05_augment` 步骤，对 `loss="True"` 的 assistant 轮次做规则增强。

默认增强器（全部为词法/语序类，不含模型类）：

| 增强器 | 作用 |
|---|---|
| `insert_filler` | 插入语气词/口头禅 |
| `synonym_replace` | 同义词替换 |
| `reorder` | 语序调整 |

配置为 `strategy=single`、`min_steps=max_steps=1`、`num_variants=1`，产物是"原始对话 + 变体"的 combined 列表。因此 `n_out ≥ n_in`，且变体与原文不是一一对应。

## 2. 为什么移除

### 原因一：任务不同源

上游增强做的是**造噪声**：结巴、重复、ASR 错误、语气词。它让文本更像"有噪声的真人对话"，不判断语义是否断裂，也不做修复。

本 Agent 做的是**语义检测 + 改写**：找出答非所问、指代断裂、事实冲突等跨轮问题，再决定回退或重写。

两者不是"谁修得更好"的关系，而是"造病"与"治病"。放在同一条单变量消融链上，比较的不是方法优劣，而是任务定义，结论无法归因。

### 原因二：不可配对

胜率与 McNemar 都要求同一 `dialogue_key` 在两个臂各出现一次。A1 输出的是变体列表：

- `n_out ≠ n_in`；
- 变体没有稳定的 1:1 映射；
- 同一原文的多个变体会让分母失真。

即使硬算一个胜率，也不是配对比较，统计工具不成立。

### 原因三：不可复现

- 当前开源环境没有安装 `pipeline` 包，A1 根本无法运行；
- 上游产物未入库，无法复盘；
- 旧锁里的 A1 指纹是在 `dirty=true` 的工作区生成的（`git_commit=fde585bb…`），不能完整描述产生指纹的代码；
- 锁已重建为 v2.0，且只含 A0。

一个无法复现、也无法归档产物的臂，留在主链上只会让"可复现基线"这个核心主张出现例外。

### 原因四：破坏单变量原则

原链 `A0 → A1 → A2 → A3` 里，A1 同时改变了**数据分布**（加噪）和**任务**（增强而非修复）。这不是"只差一个变量"。移除后主链变成：

```
A0（不处理）→ A2（单次 LLM 重写）→ A3（工具循环）→ A3L（换决策者）→ A4（加判官）
A3R 作为 A3 的修复分支，单独与 A3 对比
```

## 5. A1 的能力去了哪里

不是丢弃，而是换了用途：

1. **鲁棒性实验的噪声源**：用 `05_augment` 把干净输入变成噪声输入，同一个 Agent 分别跑 clean 与 noisy，看指标掉多少。详见 [效果验证与鲁棒性实验](2026-11-19-效果验证与鲁棒性实验.md)。
2. **上游集成的事实依据**：A1 的懒加载代码证明了"接入上游只需在调用侧转换配置"，这也是本 Agent 定位为可插拔组件（处理 JSON 即可，接不接上游都行）的依据。

## 6. 一句话结论

A1 被移除，不是因为它没用，而是因为它回答的不是这条消融链要回答的问题：**主链问"修复方法是否有效"，A1 问"加噪后的数据长什么样"。** 把它移出主链，再用它做鲁棒性实验，两个问题各自成立。
