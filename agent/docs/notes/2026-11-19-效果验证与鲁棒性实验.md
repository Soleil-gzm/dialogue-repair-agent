# 效果验证与鲁棒性实验

> 类型：实验复盘 ｜ 日期：2026-11-19
> 关联：[Benchmark 评测设计 §3.1 双轨 fixture](../architecture/Benchmark评测设计.md#31-双轨-fixture同时满足合规与开源)、[ADR D6 私有轨](../decisions/决策记录ADR.md)、[改造路线图 §3.4](../decisions/改造路线图.md)

## 1. 先给结论

"原来设计的在公司电脑上跑生产数据、量化实际效果，现在变成鲁棒性实验了" —— **这个理解不对，需要拆成两条轴。**

- **私有轨（真实生产数据）仍然是效果验证**，它回答的是"在真实数据分布上，这个 Agent 还有没有效"。
- **鲁棒性实验是一条新增的、独立的实验轴**，它回答的是"输入变脏以后，同一个 Agent 的性能掉多少"。

A1 被移出主消融链，改变的是 A1 的角色（从"对照臂"变成"噪声发生器"），**没有改变私有轨的定位**。两者不能互相替代。

## 2. 两条轴的区别

| | 效果验证（私有轨） | 鲁棒性实验 |
|---|---|---|
| 数据 | 公司真实生产对话（脱敏） | 干净输入 + 同源噪声输入 |
| 变的是什么 | 数据分布 | 输入质量 |
| 回答的问题 | 真实分布上是否仍然有效 | 噪声下性能衰减多少 |
| 对照方式 | 公开轨 vs 私有轨，指标并列 | 同一 Agent 在 clean vs noisy 上配对比较 |
| 结论用途 | 外部效度 / 能否落地 | 稳定性 / 部署风险 |
| 数据是否入库 | 否（仅聚合指标） | 可以（噪声由固定 seed 生成） |

一句话：

- 效果验证问 **"换一批真实数据，结论还成立吗？"**
- 鲁棒性问 **"同一批数据被弄脏，方法还稳吗？"**

## 3. 为什么 A1 不能当鲁棒性实验

A1 原来的做法是：把加噪后的数据当成一个新臂，和 A0 比"谁更好"。这有三处错位：

1. **比较对象错**：A1 的产物是"加噪数据"，不是"修复后的数据"。拿它和 A0 比，比的是两份数据的分布差异，不是方法效果。
2. **分母错**：A1 输出变体，`n_out ≠ n_in`，无法配对。
3. **问题错**：它回答"加噪有没有用"，而鲁棒性要回答"加噪后 Agent 还灵不灵"。

正确的用法是把 `05_augment` 当成**输入变换**，而不是**对照臂**：

```
干净输入 X ──┬──> Agent ──> 结果 R_clean
             │
             └── 05_augment(seed) ──> 噪声输入 X' ──> Agent ──> 结果 R_noisy
```

然后比较 `R_clean` 与 `R_noisy`。同一 Agent、同一任务、同一评估器，只变输入质量——这才符合单变量原则。

## 4. 鲁棒性实验怎么设计（可执行版）

### 4.1 输入与配对

- 基座：`defects_v1.jsonl`（有注入标签，可算召回）或 `base_v1.json`（看误报与保真）。
- 噪声：调用上游 `05_augment`，`augmenters={insert_filler, synonym_replace, reorder}`，固定 seed。
- 配对键：优先用原始 `dialogue_key`；若增强产物丢失了键，只取"原文 + 单变体"的子集，或在语料级比较聚合指标，并在报告 limitations 说明。

### 4.2 指标

| 指标 | 含义 | 预期 |
|---|---|---|
| 缺陷召回变化 | noisy 相对 clean 的各类召回差 | 允许下降，但需量化 |
| 误报率变化 | 干净样本被误判的比例差 | 噪声可能推高误报，重点观察 |
| 实体保真率 | 重写后实体是否仍完整 | 硬门禁，不应下降 |
| 结构不变率 | 对话结构是否被破坏 | 硬门禁，必须 = 1.00 |
| 成本变化 | token / 延迟增量 | 记录，用于判断是否值得 |
| 回退率变化 | 噪声导致多少样本触发 `fallback_keep` | 过高说明噪声超出承受范围 |

### 4.3 结论写法

- 报"噪声下召回从 X% 降到 Y%（配对差，95% CI）"，而不是"鲁棒性良好"。
- 若硬门禁在噪声下仍然成立，这是加分项；若不成立，照实报，并说明噪声类型与强度。
- 噪声强度（增强器组合、seed、变体数）必须写进 manifest，换 seed 结论不可直接复用。

## 5. 私有轨（效果验证）怎么做

维持原设计，不因为 A1 移除而改变：

1. **合规先行**：内部报备 → 脱敏 → 只发布聚合指标。
2. **同契约**：私有轨与公开轨使用完全相同的字段契约，同一份 harness 代码可跑。
3. **机器分工**：公司机（4090）跑正式实验，本地 Ollama 模型；家里机只跑通链路，产物不作正式结论。
4. **产物分层**：私有轨结果带 `run_manifest.json`，但不入库；公开轨锁与结果可入库、可复现。
5. **报告并列**：公开轨 vs 私有轨指标并列，并注明"私有轨数据不可公开，复现请用公开轨"。

## 6. 两条轴怎么组合成结论

| 组合 | 结论 |
|---|---|
| 公开轨有效 + 私有轨有效 | 方法在真实分布上成立（外部效度） |
| 公开轨有效 + 私有轨无效 | 公开轨 fixture 分布偏了，先修数据，不吹方法 |
| clean 有效 + noisy 有效 | 方法稳定，可部署 |
| clean 有效 + noisy 掉很多 | 方法可用但脆弱，需在报告写明适用输入质量 |
| 私有轨有效 + noisy 掉很多 | 真实数据里噪声水平决定效果，需先做数据清洗 |

这四类结论各自独立，不能用一个替代另一个。面试时也应分开讲：

> "我用私有轨验证真实分布上的效果，用鲁棒性实验量化噪声下的衰减，两者是外部效度与稳定性的两条轴，不是同一个实验的两个名字。"

## 7. 对路线图的影响

- 私有轨实验：仍按 S1 并行工作流推进，报备在先。
- 鲁棒性实验：新增在 S1b（与 L3 统计一起），因为它需要配对与区间，正好复用同一套统计工具。
- A1：不再作为臂，只作为噪声源被引用。
