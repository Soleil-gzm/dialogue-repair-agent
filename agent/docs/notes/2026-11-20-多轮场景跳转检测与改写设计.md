## 0. 结论先行

把改写目标定义为**「多轮上下文下，话题跳转处 assistant 的回应是否连贯合理」**是成立的，且比"给真实数据补标签"更干净。三条边界必须先钉死：

1. **user 的话题跳转：要检测，不改写。** 检测产物是"评估上下文标签 + 分层维度"，不是修复目标。
2. **判据不是"顺着 user 聊"，也不是"硬拉主线"**，而是**「回应本轮诉求 + 保持业务主线 + 跳转处有承接过渡」**三者同时成立。
3. **benchmark 主链不用改，但评估器指纹和臂清单要扩展。** "完全不用改"不成立——换 rubric 就是换尺子，按 ADR D7 必须新建 lock 并写 changelog。

一句话：**这是新增一条"多轮评测支路 + 两个新臂"，不是重写现有 benchmark。**

## 1. 问题定义：为什么单轮判定在真实数据上必然失效

### 1.1 现状（代码事实，已核对）

| 组件 | 当前输入范围 | 后果 |
|---|---|---|
| `judge.py::SYSTEM_PROMPT` 第 1 条 | "看该回复之前**最近一条** user 消息" | 只看最近一句，无历史视角 |
| `judge.py::render_dialogue` | 渲染全文（`MAX_TURNS=60`） | 文本给了，但 prompt 不让判官用 |
| `rewrite_segment._build_messages` | 只拼"客户上一句" + 待改回复 | 改写模型看不到更早历史 |
| `coherence.check_repetition` | 相邻 assistant 字面相似度 | 只抓 D5 类重复，不判跨轮承接 |

### 1.2 真实数据的结构特征

私有轨 `xiaoying-frontend_*` 由状态机多分支拼接而成：system 里是**一个**业务场景（首催/卡人/京东），但 user 轮次在不同状态分支间跳（本金查询 → 代扣卡 → 征信异议 → 私人问题 → 店铺经营 → 还款承诺）。assistant 每轮都在把它拉回催收主线。

- **单轮看**：每个 `(user_i, assistant_i)` 配对抽取时天然合理——assistant 回应了当轮诉求或拉回主线，judge 判不出违规。
- **多轮看**：user 话题跳变处，assistant 的回应出现三类不连贯——硬切无承接、被带跑丢主线、跨轮口径前后不一。

### 1.3 核心洞察

> 单轮配对抽取保证了"局部正确"，但**不合理性是被上下文"涌现"出来的**。
> 历史轮次不是噪声，而是判定所必需的参照系。

这正是现有 L1（注入即标注）无法覆盖、而 L3（成对比较）可以承接的那类问题：**不需要"哪一轮标坏了"的真值，只需要"同一批评分者判改前/改后哪个更连贯"。**

## 2. 核心决策：user 话题跳转——检测，但不改写

这是本设计的地基，回答"user 的话题转变是否有检测和改写的需要"：

| 动作 | 结论 | 理由 |
|---|---|---|
| **检测** user 话题跳转点 | ✅ 需要 | 它是多轮判官的**触发条件**和**分层维度**。不先定位跳转点，就无法判断"该处承接是否合理"；也是 R3 分层抽样里的 `scenario` 在私有轨的替代键 |
| **改写** user 话题跳转 | ❌ 不需要，且不允许 | ① 硬门禁 R1/R2/R4：system / 结构 / 说话人集合冻结；② `rewrite_segment` 契约只接受 `role == assistant` 的 turn；③ 改 user 话术 = 篡改客户原话，合规上不可接受；④ 把跳转"修平"会抹掉真实分布，外部效度归零 |

**检测产物的唯一用途**：作为 assistant 判官的上下文标签（`turn_shift=True` / `need_type=...`）和评测分层键，**绝不作为修复目标**。

---

## 3. 判据重定义：三个子维度，缺一不可

在话题跳转点 `t`，判定 assistant 回复 `a_t` 是否合格：

| 子维度 | 定义 | 反例 |
|---|---|---|
| **诉求回应** `need_answered` | 对本轮 user 的实质诉求有回应或明确说明为何不答 | user 问本金，assistant 完全不提，只重复"还款" |
| **主线保持** `mainline_kept` | 未被 user 带离业务主线 | user 聊店铺生意，assistant 跟着聊经营建议 |
| **承接自然** `bridge_natural` | 对跳转有缓冲（承认 / 过渡 / 关联），而非硬切 | 上一轮还在谈金额，本轮突然"你有孩子吗"式的生硬转换 |

新增违规类型：`C4_topic_shift_unbridged`（跨轮承接缺失），**与 D1 严格区分**：

| | D1 答非所问 | C4 跨轮承接缺失 |
|---|---|---|
| 判定范围 | 单轮：`a_t` 与 `u_t` 是否相关 | 跨轮：`a_t` 在历史上下文中的承接质量 |
| 真值来源 | 注入标签（D1 注入集） | 无 ground truth，人工 rubric 校准 |
| 在真实数据上 | 基本检不出（配对天然合理） | 主要检出对象 |
| 允许改写 | ✅ 可改写 | ✅ 可改写（仅限 assistant 轮） |

> 注意："回应本轮诉求"的口径随域而变——公开轨售后域与私有轨催收域的"合格回应"不同。这正是项目已有 `domain_profile` 设计的自然延伸：**同一套检测框架，两套 rubric 配置**，rubric 文本哈希进评估器指纹。

## 4. 检测层设计（两档，成本递增）

### 4.1 确定性检测（E1，全量跑，可复算，无真值依赖）

| 检测项 | 手法 | 产出 |
|---|---|---|
| 话题跳转点识别 | 相邻 user 轮的实体/关键词簇差异超阈值 | `turn_shift` 布尔标签 + `shift_turn` 列表 |
| 跨轮口径漂移 | 同一实体（金额/日期/承诺）在 assistant 轮次间是否一致 | `entity_drift` 违规列表 |
| 主线保持代理 | assistant 是否复述了 user 的游离话题关键词（孩子/生意/店铺） | `mainline_drift` 违规列表 |

这三项**不依赖 LLM 判官**，可离线复现，直接进硬门禁或代理指标。

### 4.2 LLM 判官（E2，软指标，需校准）

- 新 prompt 版本（如 `coherence-judge-v3-multi`），保留 v2 不动。
- 输入：带历史窗口的对话 + 确定性层给出的 `turn_shift` 标签。
- 输出：`C4` 违规列表（含 `sub_dimension` / `turn` / `detail`），只指向 assistant 轮。
- 遵守现有判官契约：强 JSON、越界丢弃、故障记 `C0_judge_error` 不静默放行、跨模型家族隔离（ADR D4）。
- **必须配 30–50 条人工 rubric 校准，κ ≥ 0.6**；未达标则只用于排序，不进结论（与 Benchmark 设计 §5.3 一致）。

### 4.3 人工层（E3，校准用）

复用 Benchmark 设计 §5.4 的 4 维 rubric，把"跨轮连贯"维度细化为本节三个子维度。同一批评分者、改前改后成对打分。

## 5. 改写层设计（历史窗口，只改 assistant）

对 `rewrite_segment` 做**向后兼容**的参数扩展：

- 新增可选 `history_window: int`（默认保持当前行为 = 只看上一句；多轮臂设为 N，如 6）。
- `_build_messages` 在"客户上一句"之前插入历史窗口摘要（system + 最近 N 轮 user/assistant），并附上 `issues` 中的 `sub_dimension`。
- 改写指令增加："对跳转处先承接再拉回主线，不改变业务事实与实体"。
- **硬门禁不变**：R1–R5 全部保留；改写后仍走 `check_consistency(before, after)`；结构/实体/system/说话人一律不得变。
- 历史轮**只读**：作为上下文输入，不作为改写对象。

## 6. Benchmark 接入：精确边界与单变量拆解

### 6.1 不用改的部分（主链）

- 臂定义 `A0/A2/A3/A3L/A3R/A4/A4R`、注入式 D1–D6、L1 定位口径、单变量原则、硬门禁、双轨设计、统计规则——**全部不动**。

### 6.2 必须扩展的部分（不是"改 benchmark"，是"加支路"）

| 扩展项 | 说明 |
|---|---|
| 评估器指纹 | 新 rubric = 换尺子 → **新建 lock + 写 `lock_changelog.md`**（ADR D7）；不改 `baseline_lock.json` 本身 |
| 臂清单 | 新增多轮臂（见 6.3），报告 `ARM_ORDER` 补登记 |
| 真值口径 | **不报定位 F1**（无 ground truth）；只报成对胜率（Wilson CI）+ 连贯性分差（paired bootstrap）+ 确定性代理指标 |
| 分层维度 | 私有轨以 `turn_shift` 替代公开轨 `scenario` 做分层 |

### 6.3 单变量拆解（关键，否则结论不可归因）

不能做一个"同时换判官 + 换改写"的臂——那同时变了两个变量，违反单变量原则。拆两级：

| 臂 | 相对基线 | 唯一变量 | 回答的问题 |
|---|---|---|---|
| `A3M` | A3 | 判官换成多轮版（只检测） | **多轮检测**本身带来多少检出增益 |
| `A3R-M` | A3M | 改写带历史窗口 | **多轮改写**相对只检测多带来多少收益 |
| `A4M` | A4 | 判官多轮版 + LLM 决策 | 多轮判官在 LLM 决策下是否仍有效 |

预期单调性（预注册）：检出率 `A0 < A3 < A3M`，连贯性胜率 `A0 < A3R < A3R-M`；硬门禁恒定通过。

## 7. 验证计划（冒烟 → 校准 → 结论）

1. **冒烟（先做，证明问题存在）**：取 20–30 条私有轨样本，跑 v2 判官与多轮判官，统计"单轮通过但多轮判失败"的样本数。若为 0，说明该问题在数据中不存在，设计前提不成立，停止。
2. **硬门禁复验**：多轮改写后 `check_consistency` 必须 100% 通过；实体保真 ≥ 0.99。
3. **人工校准**：30–50 条，双评分者，κ ≥ 0.6；κ < 0.4 重写 rubric。
4. **结论输出**：按 Benchmark 设计 §6.2 用语规范报胜率 + CI，并写 `limitations`（无 ground truth、judge 与生成同模型风险、私有轨数据不可公开）。

---

## 8. 范围边界与风险

| 项 | 边界 |
|---|---|
| 不做的 | 不改 user 轮、不改 system、不改 benchmark 主链、不做"把跳转修平"的数据清洗 |
| 真值风险 | 无 ground truth，不能报定位 F1 / 拦截率；用人工校准 + 成对比较替代 |
| 偏差风险 | judge 与生成必须跨模型家族；位置偏差用 A/B、B/A 双向评 |
| 合规风险 | 私有轨只出聚合指标，不展示原始对话；实验前按 ADR D6 报备 |
| 沉没成本风险 | 冒烟阶段若"单轮通过但多轮失败"样本为 0，及时止损，不开新臂 |

## 9. 面试防守（备用素材）

> Q：「你原来的 judge 只看单轮，为什么不直接补标签？」
> A：单轮配对抽取的数据天然局部合理，补标签等于人工造缺陷，又回到"自己造病自己治"。我把问题重新定义为"跨轮承接"——user 的话题跳转是真实分布的固有属性，要检测它作为上下文，但不改写它（改 user 就是篡改客户原话，也破硬门禁）。改写只碰 assistant，判据是"回应诉求 + 保持主线 + 承接自然"。主 benchmark 不动，新增两条单变量臂隔离"检测"和"改写"各自的净收益。

> Q：「多轮 judge 没有真值，怎么证明有效？」
> A：不证明绝对正确，只证明相对更优——同一批人工校准过的评分者做改前/改后成对比较，报胜率和 Wilson 区间；确定性层再补跨轮口径漂移这种可复算的硬指标。没有真值就诚实不报 F1，这是设计纪律不是缺陷。
