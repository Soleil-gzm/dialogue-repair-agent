# 项目笔记（notes）

> 定位：记录过程中的疑问、术语理解、决策推导与实验复盘。**笔记不是权威依据**。
> 与正式文档冲突时，以 [文档中心](../README.md) 的权威顺序为准。
> 最后修订：2026-11-20

## 1. 为什么单独建 notes/

`architecture/` 只写"系统现在是什么"，`decisions/` 只写"为什么这样定"。但过程中还有大量内容不适合塞进这两类：

- 第一次遇到的统计/评测术语，需要先用白话讲清楚；
- 一个决策被推翻的中间过程，正式文档只保留结论；
- 实验做完后的复盘：假设、结果、哪里设计错了。

这些内容统一放 `notes/`，避免两件事：① 同一个概念反复查；② 过程稿污染正式文档。

## 2. 命名与分类

文件名格式：`YYYY-MM-DD-主题.md`。

| 类型 | 典型文件名 | 放什么 |
|---|---|---|
| 术语卡片 | `YYYY-MM-DD-xxx术语.md` | 统计/评测概念的白话解释，以及在本项目里怎么用 |
| 决策过程 | `YYYY-MM-DD-xxx记录.md` | 一个决策的前因后果、备选方案、被否决的理由 |
| 实验复盘 | `YYYY-MM-DD-xxx实验.md` | 假设、变量、结果、结论、下次改进 |

规则：

1. 一篇笔记只讲一件事，主题写进文件名。
2. 笔记可以引用正式文档；**正式文档不得引用笔记作为依据**。
3. 笔记里的结论升级为正式规则时，迁入 `architecture/` 或 `decisions/`，并在笔记顶部标注 `已升格 → 路径`。
4. 新增笔记必须登记到 `oss_manifest.txt`，否则开源边界测试失败。
