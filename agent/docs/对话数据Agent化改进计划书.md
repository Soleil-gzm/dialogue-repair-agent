## 一、背景与问题定义

### 1.1 现有系统

已交付的对话数据生产系统，采用「话术模板 + 概率转移矩阵 + 继承树」生成对话数据：

- 七层分层架构、19 步端到端数据流
- 路径生成基于概率矩阵权重选择模块，A/B 集约束 + `max_repeat`
- 支撑 12 条业务线，累计生成对话数据超 80 万条
- 核心测试子集 125 项通过

### 1.2 识别的核心缺陷

**模板拼接式生成的固有天花板：**

| 缺陷 | 具体表现 |
|---|---|
| 局部通顺、全局不连贯 | 模块内部通顺，跨轮次靠概率跳转拼接，衔接生硬 |
| 多样性受限于模板库 | 组合空间大但「味道」重复 |
| 模型学到模板分布 | 训练出的模型**输出死板**，缺少对话逻辑 |

**结论：这不是实现缺陷，是「模板拼接式数据合成」方法论的天花板。**

### 1.3 改进方向

用大模型对已生成对话做**语义级增强**，逐步从「固定编排」演进到「Agent 自主决策」。

---

## 二、总体演进路线

```
阶段一：LLM 语义重写（最小验证）
    ↓  单条验证 → 批量插件化
阶段二：RAG 增强重写
    ↓  优质对话沉淀成检索库，为改写提供参考
阶段三：Agent 自主修复
    ↓  工具调用循环 + 决策链 Trace
阶段四：多视角评估
    ↓  自主判断改得好不好、要不要重试
```

**核心原则：**
- 每一步都复用已有架构（BaseAugmenter / StepRegistry / StateTracker / TraceCollector）
- 每一步都有可验证产出，做完即可写入简历
- 不做前置依赖未完成的功能，不追求一次到位

**技术选型（已确定）：**
- **手写，不上 LangChain** —— 已有 ToolRegistry 与状态追踪，复用成本低于学习框架
- **先做最简单的工具调用循环** —— 多专家 / 多 Agent 模式暂不引入

## 三、阶段详细规划

### 阶段一：LLM 语义重写（预计 11/13 – 11/16）

**目标**：验证「LLM 重写能否提升对话连贯性」这一核心假设。

#### Step 1.1 单条最小验证（11/13 下午，约半天）

- [ ] 从已生成数据中抽取 1 条对话（选能人工判断连贯性的）
- [ ] 设计 prompt：要求模型指出跨轮次衔接不自然处，并重写为更流畅版本，**保持原有意图与策略标签不变**
- [ ] 调用模型，得到重写结果
- [ ] 对比前后：连贯性是否提升？意图是否漂移？
- [ ] 记录结论

**产出**：一份前后对比记录（截图 + 结论）
**简历价值**：可写「已完成 LLM 重写方案的最小可行性验证」

#### Step 1.2 增强器插件化（11/14 – 11/16，约 2–3 天）

- [ ] 新建 `LLMRewriteAugmenter`，继承既有 `BaseAugmenter` 抽象基类
- [ ] 实现 `apply()` 方法，接入模型调用
- [ ] 利用既有懒加载机制延迟加载模型资源
- [ ] 通过 `AUGMENTER_META` 注册，`weight` 参数控制参与比例
- [ ] 在 `CompositeAugmenter` 中以 `single` / `multi_step` 策略组合验证
- [ ] 小批量（如 100 条）端到端跑通，复用既有断点续跑与任务隔离
- [ ] 记录：耗时、token 成本、意图保持率（人工抽检）

**产出**：可运行的增强器插件 + 小批量测试报告
**简历价值**：可写「设计 LLM 重写增强器插件，复用既有抽象与权重机制无缝接入，支持原始/重写数据按比例混合生产」
**关键点**：这是「新增插件」而非「新建系统」，工作量可控

---

### 阶段二：RAG 增强重写（预计 11/17 – 11/21）

**目标**：让重写不再「凭空生成」，而是参考历史优质对话。

#### Step 2.1 优质对话库构建（11/17 – 11/18）

- [ ] 梳理已沉淀的优质对话模板与场景
- [ ] 设计结构化存储格式（场景标签 + 对话内容 + 质量标注）
- [ ] 数据清洗与去重

**产出**：结构化优质对话数据集
**简历价值**：可写「从历史沉淀中构建优质对话检索库」

#### Step 2.2 检索引擎接入（11/19 – 11/21）

- [ ] 向量化方案选型（复用阶段成果：text2vec / sentence-transformers）
- [ ] 实现检索模块（向量召回 + 关键词召回，可参考 BM25 思路）
- [ ] 将检索结果作为上下文注入重写 prompt
- [ ] 对比实验：**有检索参考 vs 无检索参考**，连贯性提升差异

**产出**：带检索增强的重写增强器 + 对比实验数据
**简历价值**：可写「引入 RAG 为改写提供上下文参考，形成『检索 + 重写』两段式增强」，并说明 RAG 在此处作为重写环节的上下文增强，而非全流程

---

### 阶段三：Agent 自主修复（预计 11/22 – 11/30）

**目标**：从「固定流程重写」升级为「Agent 自主决策改哪里、怎么改」。

#### Step 3.1 工具抽象（11/22 – 11/24）

- [ ] 将以下能力抽象为可注册工具：
  - `check_coherence` —— 检查对话连贯性，输出问题位置
  - `retrieve_history` —— 检索相似优质对话（复用阶段二）
  - `rewrite_segment` —— 重写指定片段（复用阶段一）
  - `check_consistency` —— 校验重写后意图/策略标签是否漂移
  - `fallback_keep` —— 判断重写价值不大则保留原文
- [ ] 复用既有 `StepRegistry` 模式实现工具注册与动态分发
- [ ] 复用 `StateTracker` 实现会话状态持久化与断点恢复

**产出**：工具集 + 注册机制
**简历价值**：可写「将检查、检索、重写、校验抽象为可注册工具，复用自研注册表实现动态分发」

#### Step 3.2 决策循环（11/25 – 11/30）

- [ ] 实现工具调用循环：观察 → 决策 → 调用 → 反馈
- [ ] 复用既有条件路由实现分支判断
- [ ] 复用 `max_repeat` 思路设置**迭代上限**，防止死循环
- [ ] 复用错误分级机制：不可修复 → `fallback_keep`，可重试 → 追加迭代
- [ ] 复用 `TraceCollector` 记录完整决策链
- [ ] 端到端验证：输入一批拼接对话，输出修复后对话

**产出**：Agent 自主修复流程 + 决策链 Trace 样例
**简历价值**：可写「由 Agent 依连贯性反馈自主决策重写范围与重试策略，Trace 记录完整决策链」

---

### 阶段四：多视角评估（预计 12/01 起）

**目标**：解决「怎么判断改得好不好」——这是 Agent 体系中最难的环节。

- [ ] 评估维度设计：连贯性 / 意图保持 / 策略一致 / 多样性
- [ ] 实现 LLM-as-judge 多视角评估（多个 prompt 视角交叉校验）
- [ ] 规则校验补充（标签一致性、长度、禁用词等）
- [ ] 评估结果回灌决策循环，形成闭环
- [ ] 沉淀评估指标，作为数据质量报告的一部分

**产出**：评估模块 + 质量指标
**简历价值**：可写「设计多视角评估机制，支持 Agent 自主判断修复质量并决定是否重试」

## 四、成本与风险

| 项目 | 说明 |
|---|---|
| 时间投入 | 阶段一 3 天、阶段二 5 天、阶段三 9 天、阶段四开放 |
| 模型成本 | 需评估单条重写的 token 开销，小批量先测 |
| 主要风险 | 重写导致意图漂移 —— 用 `check_consistency` 拦截 |
| 次要风险 | 模型输出不稳定 —— 固定随机源 + 可复现设计（复用既有机制） |
| 兜底策略 | 任何阶段失败，保留 `fallback_keep`，原始数据不受影响 |

## 八、执行原则

1. **先跑通，再优化** —— 任何一步不允许在未跑通前追求完善
2. **复用优先** —— 新功能优先考虑能否作为插件接入既有架构
3. **产出即登记** —— 每完成一步立即更新第五节素材表
4. **不阻塞投递** —— 改造与投递并行，不得因改造推迟投递
5. **接受不完美** —— 已知技术债记录下来，不即时偿还
