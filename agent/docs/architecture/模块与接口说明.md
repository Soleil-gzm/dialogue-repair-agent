# 模块与接口说明

> 版本：v1.0  
> 最后修订：2026-11-18  
> 事实基线：Sprint 1a（`24de810`）之后的仓库代码  
> 关联文档：[架构设计](架构设计.md)、[Benchmark评测设计](Benchmark评测设计.md)、[部署与运行指南](../guides/部署与运行指南.md)

## 1. 文档定位

本文是**契约文档**：数据长什么样、工具怎么调用、运行时返回什么、CLI 收什么参数、产物有哪些字段。指标口径不在这里定义，见 [Benchmark评测设计](Benchmark评测设计.md)。

## 2. 术语与状态

### 2.1 臂（arm）

| 名称 | 含义 | 实现状态 |
|---|---|---|
| `A0` | 不处理 | 已实现（`run.py`） |
| `A1` | 上游规则增强 | 已移出主链（2026-11-19），仅作鲁棒性噪声源 |
| `A2` | 单次 LLM 重写 | 未实现（S1b） |
| `A3` | 规则策略 + 确定性工具 | 已实现（`agent_eval.py`） |
| `A3L` | LLM 决策 + 确定性工具 | 已实现 |
| `A3R` | 规则多轮策略 + 确定性工具 + `rewrite_segment` | 已实现 |
| `A4` | LLM 决策 + 确定性工具 + 语义判官 | 已实现 |
| `A4R` | LLM 决策 + 确定性工具 + 语义判官 + `rewrite_segment` | 已实现 |
| `A5-RAG` | RAG 增强 | 仅命名占位，已移出本期 |

### 2.2 结果状态

| 状态 | 触发条件 | 数据是否可信 |
|---|---|---|
| `accepted` | 策略主动 `stop`，且未触发回退 | 是 |
| `fallback` | 任意检查未通过或无法安全修复，`fallback_keep` 保留原文 | 是（未改动） |
| `stopped` | 预算触顶、死循环或不可恢复的环境中断 | 需单列，不能当作“未检出” |
| `failed` | 策略异常或工具异常 | 否 |

### 2.3 终止原因

| 常量 | 值 | 含义 |
|---|---|---|
| `TERM_STOP` | `stop` | 策略显式停止 |
| `TERM_LOOP_DETECTED` | `loop_detected` | 同一 `(工具, 参数指纹)` 重复超过阈值 |
| `TERM_TOOL_TERMINAL` | `tool_terminal` | 工具返回 `terminal=true`（如 `fallback_keep`） |
| `TERM_ERROR` | `error` | 策略或工具抛异常 |

预算触顶的终止原因来自 `Budget.exhausted()`：`max_iterations` / `max_tool_calls` / `max_tokens` / `max_wall_clock`。

## 3. 依赖方向

```text
fixtures / defects（纯数据生成）
        │
        ▼
eval（规则 / 连贯性 / 判官 / 实体抽取）      ← 不依赖 runtime
        │
        ▼
tools（eval + runtime.registry）
        │
        ▼
runtime（registry / state / budget / policy / loop / trace / ledger / llm）
        │
        ▼
benchmark（fixtures / defects / arms / run / agent_eval / report）
```

约束：`runtime` 不 import `tools`；`eval` 不 import `runtime`；`benchmark` 可以 import 全部下层。新增模块必须保持该方向，避免循环依赖。

## 4. 数据契约

### 4.1 对话对象

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "...", "loss": "True"}
  ]
}
```

| 字段 | 类型 | 约束 |
|---|---|---|
| `messages` | array | 必填，按时间顺序排列 |
| `role` | string | `system` / `user` / `assistant`；当前数据固定这三种 |
| `content` | string | 必填 |
| `loss` | string | 可选；当前公开轨为字符串 `"True"`，结构校验按原值严格比较，不做类型转换 |

规则校验（R2）比较消息数、每条 `role` 与 `loss` 原值；缺少或多出字段都视为结构变化。

### 4.2 公开轨 fixture

| 文件 | 条目数 | 用途 | 生成方式 |
|---|---|---|---|
| `agent/fixtures/public/base_v1.json` | 12 | A0 基线、缺陷注入源、干净样本干预测量 | `--n 12 --seed 20261112` |
| `agent/fixtures/public/dev_v1.json` | 30 | 调 prompt / 调策略 | 与 test 一起从 80 条分层切分，`split-seed 20261118` |
| `agent/fixtures/public/test_v1.json` | 50 | 最终结论，只在收尾时使用 | 同上，与 dev 不重叠 |
| `agent/fixtures/public/defects_v1.jsonl` | 120 | 六类缺陷各 20 条 | `--per-type 20 --seed 20261113` |

生成命令见 [部署与运行指南](../guides/部署与运行指南.md#3-数据生成)。

### 4.3 缺陷记录

```json
{
  "sample_key": "D1_off_topic-000",
  "dialogue": {"messages": ["..."]},
  "defect": {"type": "D1_off_topic", "turn": 4, "field": "content"},
  "base_index": 0
}
```

评测侧依赖的字段：

| 字段 | 用途 |
|---|---|
| `sample_key` | 样本稳定标识 |
| `dialogue` | 注入缺陷后的对话，作为 Agent 输入 |
| `defect.type` | 指标按类型分组 |
| `defect.turn` | 注入轮次；定位判定允许 ±1 |
| `base_index` | 从 `base_v1.json` 取干净原文作为回退参照 |

## 5. 工具契约

所有工具的返回值必须是 `dict`。通用字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `ok` | bool | 工具是否执行成功（不代表对话合格） |
| `violations` | array | 违规明细，元素为 `{rule, detail, turn}` |
| `violation_count` | int | 违规数量 |
| `terminal` | bool | 是否终止决策循环 |
| `status` | string | 终止时的结果状态 |
| `tokens` | int | 本次工具内部模型调用消耗的 token |

`ToolRegistry.invoke` 会拦截非 `dict` 返回值并抛 `ToolContractError`。

### 5.1 `check_consistency`

- **作用**：校验重写前后对话是否保持硬约束。
- **注册**：默认工具集。
- **入参**：

```json
{
  "before": {"messages": ["..."]},
  "after": {"messages": ["..."]}
}
```

- **返回**：`{ok, violation_count, violations}`；入参不是对话对象时返回 `R0_input_contract`。
- **规则码**：`R1_system_immutable`、`R2_structure_invariant`、`R3_entity_fidelity`、`R4_speaker_set`、`R5_role_content_leak`。
- **终止**：否。

### 5.2 `check_coherence`

- **作用**：检查对话自身连贯性。
- **注册**：默认工具集；`register_all(judge=...)` 注入语义判官后可检出 D1。
- **入参**：`{"dialogue": {"messages": ["..."]}}`
- **返回**：`{ok, violation_count, violations, tokens}`；入参非法返回 `C0_input_contract`。
- **规则码**：`C0_input_contract`、`C0_judge_error`、`C1_assistant_repetition`、`C2_degenerate_turn`、`C3_off_topic`。
- **失败策略**：判官异常记为 `C0_judge_error` 并按违规处理（fail-closed）。
- **终止**：否。

### 5.3 `fallback_keep`

- **作用**：放弃修改，保留原文。
- **注册**：默认工具集。
- **入参**：`{"original": {"messages": ["..."]}}`
- **成功返回**：`{ok: true, terminal: true, status: "fallback", dialogue, reason}`。
- **失败返回**：`{ok: false, terminal: true, status: "failed", error}`。
- **终止**：是。

### 5.4 `rewrite_segment`

- **作用**：只重写指定的 assistant 轮次；策略层负责定位与下指令。
- **注册**：**不在默认工具集**；A3R 臂通过 `make_rewrite_segment(client, ...)` 注册。
- **构造参数**：`temperature=0.3`、`max_tokens=512`、`run_id`。
- **入参**：

```json
{
  "dialogue": {"messages": ["..."]},
  "turn": 4,
  "issues": [{"rule": "C3_off_topic", "detail": "...", "turn": 4}]
}
```

- **成功返回**：`{ok: true, status: "rewritten", dialogue, rewritten_turn, violation_count: 0, violations: [], tokens}`。
- **失败返回**：`{ok: false, violation_count: 1, violations: [{rule, detail, turn}], tokens}`。
- **失败码**：

| 码 | 含义 |
|---|---|
| `W0_invalid_turn` | 对话结构非法、下标越界或目标轮不是 assistant |
| `W1_parse_error` | 模型输出不是合法 JSON 对象 |
| `W2_empty_content` | 重写结果为空 |
| `W3_unchanged` | 重写结果与原回复相同 |
| `W4_llm_error` | 模型调用失败（异常已被工具吸收，不会让循环直接 failed） |

- **模型档位**：`stage="generate"`；带 `run_id` 与对话内容哈希 `dialogue_key` 写 ledger。
- **终止**：否（失败由策略继续决策或回退）。

### 5.5 工具注册

| API | 说明 |
|---|---|
| `register_all(judge=None)` | 注册默认三件套；传入 judge 时绑定到 `check_coherence` |
| `ToolRegistry.register(tool)` | 注册；名称空、重复、schema 非 dict 时抛 `ToolContractError` |
| `ToolRegistry.invoke(name, state, args)` | 分发并校验返回类型 |
| `ToolRegistry.list_tools()` / `specs()` | 名称列表 / LLM 可用的工具描述 |
| `ToolRegistry.clear()` | 清空；评测每臂开始前必须调用，避免跨臂污染 |
| `ToolRegistry.snapshot()` / `restore(snap)` | 保存/恢复注册表，供测试隔离 |

## 6. 运行时契约

### 6.1 `Decision` 与 `Policy`

```python
@dataclass(frozen=True)
class Decision:
    action: str          # "call_tool" | "stop"
    tool: str = ""
    args: dict = ...
    reason: str = ""
```

- `RulePolicy(rewrite_tool="rewrite_segment", ...)`：检查 → 定位 → 重写 → 复检；未配置 `rewrite_tool` 时只检查 + 回退。
- `LLMPolicy(client, ...)`：模型只选择工具名，参数由 `_build_args` 从状态生成，避免模型伪造整段对话。
- 策略异常由循环捕获并记为 `policy_error`，最终状态 `failed`。

### 6.2 `AgentRuntime.run`

```python
result = AgentRuntime(policy, budget=..., trace=..., registry=...).run(dialogue, reference=None)
```

`AgentResult` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `accepted` / `fallback` / `stopped` / `failed` |
| `dialogue` | dict | 最终对话（回退时为原文） |
| `termination` | string | 终止原因 |
| `reason` | string | 人类可读说明 |
| `iterations` | int | 实际迭代轮次 |
| `tool_calls` | int | 工具调用次数 |
| `tokens` | int | 循环内累计 token（含策略与工具） |
| `issues` | array | 当前仍未解决的违规 |
| `seen_issues` | array | 曾经检出的违规（只增不减） |
| `trace` | array | 本次运行的 Trace 记录 |

`ok` 属性仅在 `accepted` / `fallback` 时为 `True`。

### 6.3 `Budget`

| 字段 | 默认值 | A3R 覆盖 |
|---|---|---|
| `max_iterations` | 3 | 20 |
| `max_tool_calls` | 6 | 24 |
| `max_tokens` | 6000 | 20000 |
| `max_wall_clock_s` | 120.0 | 300.0 |

- 每次迭代开始先检查预算；任一触顶即停止，不允许“再试一次”。
- `Budget.snapshot()` 输出已用量与上限，可写入报告。

### 6.4 `AgentState`

| 字段 | 说明 |
|---|---|
| `dialogue` | 当前候选版本 |
| `original` | 原文，供校验参照与回退 |
| `budget` | 本条对话的预算实例 |
| `history` | 工具调用记录（只存参数键，不存全文） |
| `issues` | 当前未解决违规 |
| `seen_issues` | 历史检出违规（修复成功后不清空） |
| `status` | `running` 或 `fallback` |
| `result_dialogue` | 回退结果 |
| `key` | 当前候选内容的稳定哈希 |

### 6.5 `TraceWriter`

JSONL，逐行 flush；未给路径时只留在内存。事件类型：

| `event` | 何时写 |
|---|---|
| `start` | 循环开始 |
| `budget_exhausted` | 预算触顶 |
| `policy_error` | 策略异常 |
| `decision` | 每次策略决策（含被拒绝的决策） |
| `loop_detected` | 重复调用判定 |
| `tool_error` | 工具异常 |
| `tool_result` | 每次工具返回 |
| `end` | 循环结束，含 `status` 与 `termination` |

每条记录自动补 `seq` 与相对毫秒 `t_ms`。

### 6.6 `ItemCheckpoint`

- `is_done(key)`：条目是否已完成。
- `mark(key, status, **extra)`：标记完成状态。
- `completed`：已完成条目数。
- 当前类已实现，但批量评测循环尚未默认接入（S1b）。

## 8. 配置契约

`.env` 不入库；`.env.example` 是模板。代码中不出现机器名、显卡型号等本机差异（ADR D7）。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 空 | 生成侧密钥；缺失时在线臂直接报错退出 |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 生成侧模型 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容端点 |
| `JUDGE_MODEL` | 空 | 判官模型；留空沿用生成侧；温度强制 0 |
| `OLLAMA_BASE_URL` | `http://localhost:11434/v1` | 本地模型端点预留 |
| `OLLAMA_MODEL` | 空 | 本地模型名预留 |

规则：

- 密钥只从环境变量读取；`LLMSettings.redacted()` 是可安全写入日志的视图。
- `generate` 与 `judge` 通过 `StageRoutedClient` 分侧；`judge_settings()` 强制 `temperature=0.0`。
- 缺少密钥抛 `MissingCredentials`，CLI 以退出码 2 结束。

## 10. 扩展检查清单

新增工具时：

1. 在 `agent/tools/` 实现 `FunctionTool`，返回 `dict`，失败也要带 `violations` 或 `error`；
